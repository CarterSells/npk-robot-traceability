## Where to use this template

Copy this file into an approved private location outside the repository and public assets before entering real information. Keep this repository copy blank. No private storage location has been configured by this task. If a later task introduces private storage within a repository, first configure exclusions and verify tracked files; ignore rules alone do not remove already tracked data.

Keep permissions limited to the people doing this work. Do not put credentials or raw customer artifacts into the tracker. Store only approved references in the private copy and keep sharing/retention restrictions with the corresponding evidence. Public progress may contain non-sensitive aggregate counts only.

## Prospect register

Use one row per company/opportunity; put additional contacts and dated activity in the private event log. The date is the next action's due date; activity dates belong in the event log. Fit is a hypothesis until supported by a conversation or other reliable evidence.

| Prospect ID | Connection route | Introducer | Company | Role | Evidence of fit | Stage | Next action | Date (YYYY-MM-DD) | Action owner |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| | | | | | | | | | |

Stages: identified, introduction requested, introduction made, conversation completed, example shared, pilot agreed, pilot started, paid customer, paused, or closed. Direct conversations can skip introduction stages; do not fabricate intermediate events. Record why an opportunity is paused or closed. Distinguish a pilot agreement from actual start and an expressed interest in payment from a verified paid customer.

## Activity and evidence log

Add a row for each real event so moving an opportunity forward does not erase funnel history. A drafted message is not a sent message or introduction request.

Evidence references should distinguish received evidence, participant-reported estimates, and founder interpretation. Link a willingness-to-test commitment to a specific next action and track actual receipt of the permitted incident separately. Correct errors with a dated note rather than erasing the prior record.

Maintain cumulative funnel counts from the dated event log: introductions requested, introductions made, conversations, shared examples, started pilots, and paid customers. Keep these counts distinct from the current stage of each opportunity. Apply the counting definitions in [customer discovery](customer-discovery.md) in the repository; after copying this file outside the repository, that relative link may need to be replaced with an approved reference.

Review both supporting and contradicting evidence before advancing. No target, conversion, contact, or commitment is established merely by creating this template.
